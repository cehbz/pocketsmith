# pocketsmith: design

## Model
- **Developer key:** the secret PocketSmith issues a user, sent with every request; it grants access to that one user's data. The command finds it through a 1Password reference, the only setting in its config file: a config with no reference or with an unknown setting is refused, and a failed or empty 1Password read is an error that carries 1Password's error output and never its standard output, which may hold the key. A request PocketSmith refuses is reported with its method, path, status and the start of PocketSmith's reply, never with the key.
- **User:** the PocketSmith user the developer key belongs to, with an identity and a time zone. PocketSmith names the zone by a display name; the user's profile resolves it to a location through PocketSmith's list of time zones, and a zone the list doesn't name is an error. A user has categories and transaction accounts, and the command's "today" is the date in the user's time zone.
- **Category:** one of the user's categories, with an identity and a title. PocketSmith holds categories as a tree; the client lists them flat, each parent before its children, without the parent relationship.
- **Transaction account:** the account a transaction belongs to, with an identity and a name.
- **Transaction:** one entry in a transaction account, with an identity, a calendar date, an amount (a debit is negative), a payee, at most one category, whether it needs review, its labels, its transaction account, whether it is a transfer, and the account's closing balance after it. A transaction PocketSmith gives without a category is uncategorized, one without labels has none, one without a transfer flag is not a transfer, and one without a closing balance has a balance of zero. A transaction whose date is not a calendar date is an error.
- **Selection:** picks the transactions of either one user or one transaction account, never both or neither, dated from a first day to a last day inclusive, and optionally only those needing review. Listing a selection returns every transaction it picks, across all of PocketSmith's pages.
- **Update:** sets a transaction's category, review flag and labels together. No category uncategorizes the transaction, and no labels clears them.
- **Transactions command:** prints the transactions a selection picks, one JSON object per line, for use from a shell or a Claude Code session. A transaction is printed with its identity, date, amount, payee, category and account (each by identity and name or title), review flag, labels and transfer flag, but not its closing balance; an uncategorized transaction prints category zero with an empty title, no labels print as an empty list, and characters are printed as they are, unescaped. With no dates given, the range is the 90 days ending today in the user's time zone; a last day alone gives the 90 days ending on it. It selects the user's transactions across every account unless one account is named. A first day after the last, a date not in `YYYY-MM-DD` form, or a stray argument is an error.

## Tests
- Pending mark: `pending(t)`, defined in `pending_test.go` in each package with model-level tests (the root package and `cmd/pocketsmith`), called first in a model-level test, skips it until its task removes the call; `RUN_PENDING=1` in the environment runs pending tests.
- Model-level tests are every `*_test.go` except `*_unit_test.go`, in the root package and `cmd/pocketsmith`, run with `go test ./...`. The client's tests run it against a local `httptest` server (`server` in `pocketsmith_test.go`), which checks every request carries the developer key; the command's tests call its flag parsing, config loading, key reading (against a stand-in `op` script) and output directly. A unit test below a domain object's interface goes beside the code in a `*_unit_test.go` file.
